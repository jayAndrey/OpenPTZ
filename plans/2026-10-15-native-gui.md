# Нативный GUI OpenPTZ — план реализации

**Цель:** отдельное оконное приложение OpenPTZ с живым изображением и PTZ без браузера и `getUserMedia` на Windows, Linux и macOS.

## Состояние на 15 октября 2026 года

- Реализованы три режима: `gui` открывает нативное окно с видео, PTZ и пресетами; `ui` отдаёт видео и управление через HTTP; `tui` сохранил прежний маршрут запуска. Видео захватывает выбранная OpenPTZ камера через Nokhwa (Media Foundation, V4L2 или AVFoundation), поэтому браузеру не требуется разрешение на камеру.
- На Logitech Rally в Windows аппаратно проверены живое изображение и поворот из нативного окна. В release-сборке при 1280×720 измерено около 24 кадров/с в `gui` и 19 кадров/с в `ui`; поток `ui` просмотрен в браузере. Результаты зависят от устройства и освещения.
- Подготовлены ярлыки Windows/Linux, AppImage, macOS `.app` с описанием доступа к камере и сборочные зависимости Linux CI. Windows прошёл форматирование, Clippy и 28 тестов.
- До заявления о полной поддержке Linux/macOS нужны сборка и аппаратная проверка на каждой ОС, включая фактическое PTZ на macOS. Также остаются испытания установленных пакетов и отдельного сетевого клиента. Минимальная версия Rust повышена до 1.88, для неё добавлен job `msrv` в CI. Выбор камеры и разрешения, снимок и click-to-aim в нативном окне реализованы; автоматическое переподключение видео после потери камеры реализовано, но проверка из другой машины в локальной сети ещё не выполнена.

### Что завершить в следующем проходе

- [ ] На Linux собрать приложение и проверить `gui`, `ui`, `tui`, видео и PTZ на физической камере; испытать `.deb` и AppImage. На этой Windows-машине доступ к WSL отклонён, поэтому Linux-проверка здесь не выполнена.
- [ ] На macOS собрать универсальный `.app`, проверить системный запрос на камеру, живое видео и фактическое движение PTZ. Исправить нынешнюю зависимость PTZ от внешнего `uvc-util` и подтверждать результат чтением устройства.
- [ ] Проверить доступ к `ui` с отдельного компьютера в локальной сети. Автоматическое переподключение видео после отключения камеры реализовано; проверка из другой машины и повторного подключения на оборудовании ещё не выполнена.
- [ ] Проверить установленные Windows-пакеты MSI/Inno. Минимальная версия Rust повышена до 1.88, job `msrv` в CI выполняет `cargo check --all-targets --locked` на этой версии; GitHub CI для Linux/macOS должен подтвердить сборку после публикации изменений.
- [x] Добавить в нативный GUI выбор камеры/разрешения, снимок и click-to-aim (реализовано).

**Архитектура:** GUI обращается к существующим `CameraDevice` и `PresetManager` напрямую. Видео поступает из платформенного API захвата через общую модель кадров в нативное окно; HTTP-сервер остаётся отдельным интерфейсом для автоматизации и веб-клиентов. Захват и PTZ должны работать с одной выбранной физической камерой.

**Предлагаемый стек:** Rust, нативный оконный UI на `eframe/egui`, Windows Media Foundation, Linux V4L2, macOS AVFoundation. Версию UI-библиотеки нужно зафиксировать после проверки требования Rust 1.88+: у `eframe` 0.30 указан MSRV 1.80, а новые версии повысили его ([история eframe](https://github.com/emilk/egui/blob/main/crates/eframe/CHANGELOG.md)). `eframe` поддерживает нативные окна Windows, Linux и macOS и имеет совместимую с проектом двойную лицензию ([проект egui](https://github.com/emilk/egui)).

## Исходное состояние и границы

- До начала реализации `src/main.rs` запускал для `ui`/`gui` сервер из `src/api/mod.rs` и внешний браузер. `src/api/web/index.html` получал видео через `getUserMedia`; нативного видеозахвата в приложении не было.
- Управление PTZ уже разделено по ОС в `src/camera/backend/`; Linux использует V4L2, Windows — DirectShow. macOS сейчас обнаруживает камеры через `system_profiler`, а PTZ-команды передаёт необязательной утилите `uvc-util` без проверки результата (`src/camera/backend/macos.rs`). Поэтому нативное видео само по себе ещё не означает работающий PTZ на macOS.
- По уточнённому требованию: `openptz gui` открывает нативное окно; `openptz ui` поднимает сетевой интерфейс с видео и PTZ как для localhost, так и для других устройств; `openptz tui` сохраняет прежнее поведение. Ярлыки основного GUI запускают `gui`.
- Нативный путь не требует разрешения **браузера**. Системные ограничения остаются: [настройка камеры Windows](https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-privacy-setting), [разрешение macOS](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos), [Camera Portal в sandbox Linux](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Camera.html).

Дополнительные источники и оценка Linux/macOS: [исследование нативного захвата](./2026-10-15-native-camera-research.md).

## Решения по платформам

| ОС | Захват для обычной установки | PTZ | Особый случай |
| --- | --- | --- | --- |
| Windows | Media Foundation: перечисление устройства по symbolic link, `Source Reader`, кадры для текстуры GUI ([устройство](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-devsource-attribute-source-type-vidcap-symbolic-link), [Source Reader](https://learn.microsoft.com/en-us/windows/win32/medfound/source-reader)). | Сохранить проверенный DirectShow backend. | Доступ может быть выключен в Windows Settings. |
| Linux | V4L2 на выбранном `/dev/video*`: согласовать формат и захватывать кадры потоковыми буферами ([Linux Kernel](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/dev-capture.html)). | Использовать существующие V4L2 controls/XU. | Для сложных встроенных камер рассмотреть [libcamera](https://libcamera.org/faq.html); Flatpak Camera Portal даёт PipeWire-видео, но не обещает доступ к PTZ ioctl. |
| macOS | AVFoundation: `AVCaptureSession` и `AVCaptureVideoDataOutput` для кадров общего GUI ([Apple](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutput)). | Отдельно заменить либо надёжно встроить нынешнюю внешнюю UVC-команду, затем проверить движение и ошибки на устройстве. | Системное разрешение TCC и `NSCameraUsageDescription` в `.app`; браузерного запроса нет ([Apple](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos)). |

## Этапы реализации

### 1. Контракт команды и UI-библиотека

**Файлы:** `Cargo.toml`, `Cargo.lock`, `src/cli.rs`, `src/main.rs`, `src/lib.rs`, новый `src/desktop/mod.rs`.

- Проверить сборку выбранной версии `eframe` на Rust 1.88 (минимальная версия проекта) и в текущих Windows/Linux/macOS CI. Если совместимая версия неприемлема, оформить отдельное решение о повышении MSRV до изменения `Cargo.toml`.
- Переназначить `gui` нативному режиму без HTTP-сервера и браузера. Камеру открывать один раз в сессии приложения; ошибки открытия показывать в окне.
- Критерий: `openptz gui` открывает нативное окно без слушающего HTTP-порта; `openptz ui` выдаёт видеопоток и управление по сети; `openptz tui` сохраняет прежнее поведение.

### 2. Общая модель видеозахвата

**Файлы:** новые `src/video/mod.rs`, `src/video/types.rs`, платформенные `src/video/windows.rs`, `src/video/linux.rs`, `src/video/macos.rs`; при необходимости `src/camera/types.rs`.

- Определить единый идентификатор устройства, доступные режимы видео, формат кадра, время кадра, ошибки отключения и методы запуска/остановки. Привязать идентификатор к устройству `CameraDevice`, а не искать видеокамеру только по имени.
- Передавать в GUI только последний готовый кадр через ограниченный буфер; при отставании отбрасывать старые кадры. Нормализовать форматы для текстуры, сохраняя корректный цвет и соотношение сторон.
- Проверить переключение камер, отсутствие камеры, занятое устройство и отключение USB без зависания окна. На этапе разработки использовать тестовый источник кадров, который не требует оборудования.

### 3. Нативное окно и функции управления

**Файлы:** `src/desktop/mod.rs` и модули интерфейса внутри `src/desktop/`; использовать `src/presets.rs` и существующий `CameraDevice`.

- Перенести живое превью, выбор камеры и разрешения, D-pad, Home, zoom, сохранение/вызов пресетов, состояние камеры, снимок и click-to-aim. Вызывать камеру напрямую, без HTTP-запросов к локальному серверу.
- Разделить поток захвата и цикл UI. Показывать отсутствие кадра, отказ в доступе и неподдерживаемый PTZ явно; не отображать кэш координат как подтверждённое движение.
- Критерий: нативное окно остаётся отзывчивым при 1080p и движении камеры; выбранная для превью камера совпадает с выбранной для PTZ.

### 4. Windows: первый полный аппаратный проход

**Файлы:** `src/video/windows.rs`, при необходимости `src/camera/backend/windows.rs`, `Cargo.toml`.

- Перечислить видеоустройства Media Foundation по символическим ссылкам и связать их с существующими путями DirectShow. Читать кадры через Media Foundation; выбрать поддерживаемые разрешение и частоту без неограниченного накопления кадров.
- Проверить на Logitech Rally: живое изображение, смену разрешения, Pan/Tilt в обе стороны, zoom, Home и чтение фактических координат. Повторить запуск без браузера и без внешнего видеопроцесса.
- Критерий: при ошибке захвата или PTZ окно сообщает о ней; команды не меняют индикацию координат без подтверждения драйвера.

### 5. Linux: прямой V4L2-захват

**Файлы:** `src/video/linux.rs`, при необходимости `src/v4l2/device.rs` и `src/v4l2/ioctl.rs`.

- Использовать выбранный capture-узел V4L2; отличать видеопоток от metadata-узла, согласовать реальные форматы устройства и освобождать буферы при остановке. Низкоуровневые `unsafe` операции оставить внутри проверенных обёрток драйвера.
- Проверить поток и PTZ одновременно на физической UVC-камере; отдельно проверить перезапуск после отключения устройства. Для пакетной обычной установки использовать доступ к `/dev/video*` согласно настройкам системы.
- Поддержку Flatpak/PipeWire вынести в самостоятельный этап после проверки доступа к PTZ: Camera Portal открывает видеопоток, но не заменяет V4L2 ioctl ([портал](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Camera.html)).

### 6. macOS: AVFoundation и достоверный PTZ

**Файлы:** `src/video/macos.rs`, `src/camera/backend/macos.rs`, новая конфигурация `.app` в `packaging/macos/`.

- Выбирать `AVCaptureDevice` по устойчивому идентификатору, читать кадры через `AVCaptureVideoDataOutput`, корректно обрабатывать TCC: первый системный запрос, отказ и повторный запуск после разрешения.
- Проверить реальный механизм UVC PTZ на macOS; заменить зависимость от установленного пользователем `uvc-util` или включить проверенный механизм управления в пакет. Не сообщать об успехе по одному лишь изменению кэша; неподдерживаемые команды возвращают ошибку. AVFoundation video zoom не считать эквивалентом механического UVC zoom без аппаратной проверки.
- Добавить `NSCameraUsageDescription` и необходимые права подписи для выбранного способа упаковки ([Apple](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos), [camera entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.camera)). Полная поддержка macOS PTZ допускается к выпуску только после теста на реальной камере.

**Файлы:** `installer/windows/openptz.iss`, `wix/main.wxs`, `assets/openptz.desktop`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `README.md`, `docs/ARCHITECTURE.md`, `Cargo.toml`.

- Перевести ярлыки GUI на `openptz gui`, оставив сетевой интерфейс доступным через `openptz ui`. Собирать macOS `.app` с описанием доступа к камере; проверить набор библиотек и лицензии пакетов для каждой ОС.
- Обновить описание архитектуры и матрицу реально проверенных возможностей. Добавление интерфейса и платформенных драйверов оформить минорным выпуском по политике версионирования проекта.

## Приёмка

1. На каждой ОС: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`; дополнительно проверка сборки с поддерживаемой минимальной версией Rust.
2. На оборудовании каждой ОС: изображение именно выбранной камеры, непрерывный поток, Pan/Tilt и Home с аппаратным чтением результата, обработка отключения и повторного подключения.
3. Нативный режим не запускает браузер и не требует разрешения браузера. Системные запросы ОС и портала отображаются честно; отказ не маскируется изображением другой камеры или успехом PTZ.
4. Проверить установленные Windows/Linux/macOS пакеты, ярлыки, первый запуск и права доступа к камере. Зафиксировать невыполненные аппаратные сценарии как блокирующие для заявления о полной поддержке соответствующей ОС.
